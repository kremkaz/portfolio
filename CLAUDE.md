# CLAUDE.md

Портфолио-сайт Евгении — UX/product design. Личный кейс-стади сайт с несколькими проектами (Vecta, Tanuki, приложение для отслеживания сна и другие по мере добавления).

## Стек
- **Framework:** Next.js (App Router)
- **Стили:** Tailwind CSS v4 — CSS-first конфиг, БЕЗ `tailwind.config.js`, всё через `@theme` в CSS
- **Компоненты:** shadcn/ui, база — Base UI
- **Пакетный менеджер:** pnpm
- **Деплой:** GitHub Pages. Next.js на GH Pages = статический экспорт, это накладывает конкретные ограничения:
  - в `next.config` обязательно `output: 'export'`
  - никаких server actions, API routes, ISR — только то, что можно посчитать на этапе сборки
  - `next/image` — с `unoptimized: true` (GH Pages не даёт серверной оптимизации картинок)
  - если сайт не на кастомном домене, а на `username.github.io/repo-name` — прописать `basePath`/`assetPrefix` в `next.config`, иначе пути к ассетам сломаются
  - публикация — GitHub Actions: сборка → `out/` → пуш в ветку `gh-pages` (или через официальный action `actions/deploy-pages`)
- **Шрифт:** Inter везде (не Inter Tight)

## Источники правды — читать перед версткой/стилизацией
- `design-tokens.md` — все цвета, типографика, структура карточки кейса, структура блока навыков. Не хардкодить hex-значения в компонентах — заводить как CSS-переменные/Tailwind-токены по этому файлу.
- `animations.md` — паттерны анимаций (scroll-reveal, стагтер, page transition, раскрытие карточек). Смотреть перед тем как писать любую motion-логику — не придумывать анимации от себя.
- `content/*.md` — тексты и структура каждого кейс-стади, отдельный файл на кейс. Не писать проектный текст в компонентах — компонент рендерит контент, а не хранит его.

## Правила
- Никаких произвольных цветов вне токенов из `design-tokens.md`. Если нужен новый оттенок — сначала добавить в токены, потом использовать.
- Интерфейс и весь контент — на русском. В копирайтинге избегать конструкций "не то..., а это" ("не просто X, а Y" и подобные) — так Евгения не пишет.
- Карточка кейса — переиспользуемый компонент по спеке из `design-tokens.md` (медиа сверху → теги → заголовок → подзаголовок → описание → разделитель → футер год/ссылка), а не одноразовая вёрстка под каждый кейс.
- Мобильная адаптивность обязательна для каждой секции, не только desktop-first.
- Если чего-то не хватает в токенах/спеке для реализации — не додумывать самостоятельно, спросить.

## Структура проекта (ориентир)
```
/app                  — страницы (App Router)
/components/ui        — компоненты shadcn (не трогать вручную без причины)
/components            — свои компоненты (CaseCard, SkillPill, и т.д.)
/content/*.md          — тексты кейсов
design-tokens.md
animations.md
```
