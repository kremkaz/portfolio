# Анимации референса: toan.framer.website/anz

Разбор сделан по кадрам скринкаста (2560×1606, 60fps, 39.5с), не по живому сайту — тайминги и easing ниже оценочные (по числу кадров между состояниями), для точных значений нужно смотреть DevTools/Figma Smart Animate самого сайта.

## 1. Скролл-реveal контента (основной паттерн на странице кейса)

Каждый смысловой блок (заголовок секции, текстовый абзац, диаграмма, блок Challenge/Solution) при входе в вьюпорт анимируется из состояния "невидимо/ниже" в "видимо/на месте":

- **Свойства:** opacity 0→1 + небольшой translateY (по кадрам — сдвиг незначительный, 10-20px, не "наезд снизу", а лёгкое всплытие)
- **Стагтер:** элементы внутри секции появляются не одновременно, а по очереди — сначала заголовок, потом текст, потом визуал (диаграмма/картинка). Задержка между детьми на глаз ~0.05-0.1с
- **Длительность одного элемента:** ~0.3-0.4с
- **Где встречается:** заголовки "02. ROLE", "03. KEY CHALLENGES", блоки Challenge/Solution, треугольные/пирамидальные диаграммы ("UX Prioritization Model", "Stakeholder Management Principles")
- **Реализация (Framer Motion):** `initial={{opacity:0, y:16}} whileInView={{opacity:1, y:0}} viewport={{once:true}}` на родителе с `staggerChildren` в variants

## 2. Смена секции intro → overview

Между статичным hero-заголовком ("Balancing Innovation with Legacy Systems") и следующим блоком нет резкого скролла — текст сначала теряет насыщенность (плавно сереет/бледнеет, opacity вниз), и только потом визуально сменяется следующим заголовком. Похоже на короткий opacity-переход самого текста поверх обычного скролла, а не просто скролл вьюпорта.

## 3. Горизонтальная галерея скриншотов (раздел "Legacy Systems" / роль)

Ряд телефонных моков (тёмно-бордовые рамки) появляется не всей группой разом, а с горизонтальным сдвигом и стагтером — каждый следующий мок наезжает вслед за предыдущим (translateX + fade), пока не выстроится в ровный горизонтальный ряд. Это НЕ scroll-jacking (страница не залипает и не скроллится горизонтально) — просто entrance-анимация группы при входе секции в вьюпорт.

- **Реализация:** контейнер с `staggerChildren`, каждый child: `initial={{opacity:0, x:40}} animate={{opacity:1, x:0}}`

## 4. Переход между страницами (навигация, ~30 сек на видео)

При переходе со страницы кейса на главную:

1. Текущий контент теряет резкость и прозрачность одновременно (похоже на `opacity` + `filter: blur()` на выход, ~0.2-0.3с)
2. Короткая полностью "пустая"/почти белая фаза
3. Контент новой страницы появляется тем же способом в обратную сторону: blur→resolve + opacity 0→1 (~0.3-0.4с)

Это классический Framer Page Transition (exit/enter c blur+fade), а не мгновенная смена или обычный browser-переход.

- **Реализация:** `AnimatePresence mode="wait"` на уровне layout, exit/enter variants с `filter: 'blur(8px)'→'blur(0px)'` и opacity

## 5. Карточки кейсов на главной (нижний блок "Case Studies")

Самое интересное место на записи. Карточки (розовая "Balancing Innovation with Legacy Systems", зелёная "Six Months. Four Projects.") не статичны — при входе в вьюпорт:

- Сначала видна компактная "свёрнутая" версия — только цветной тег-иконка + заголовок в одну строку
- Затем карточка **увеличивается по высоте**, поочерёдно открывая: подзаголовок → описание → иллюстрацию/скриншот интерфейса
- Карточки анимируются **не синхронно** — розовая (первая по порядку) раскрывается чуть раньше зелёной, с явным стагтером между карточками
- Внутри карточки для ANZ — декоративная 3D-иллюстрация (градиентные блобы, подписанные "September Bloom" / "August Rise"); для второй карточки — скриншот дашборда

Похоже на auto-height reveal: контейнер карточки не имеет фиксированной высоты, а контент монтируется поэтапно (каждый блок — свой `whileInView`), из-за чего высота визуально "вырастает".

- **Реализация:** каждая секция карточки — свой мотion-блок с `viewport={{once:true}}`, `transition={{delay: index * 0.15}}` на уровне списка карточек

## 6. Курсор при наведении на карточки

В конце записи видно, что при наведении на кликабельную карточку курсор увеличивается в кружок. **Не уверен на 100%**, что это дизайн сайта, а не системная опция "show clicks" в самом скринкастере (macOS/QuickTime часто рисует такой индикатор клика поверх записи). Если решишь повторять — проверь на живом сайте без записи экрана, это легко спутать.

## Что не попало в запись

- Первичная анимация загрузки hero-блока (видео начинается уже на статичном состоянии) — если нужна, придётся отдельно записать первую секунду после открытия страницы
- Hover-состояния ссылок/кнопок (цвет, underline) — в кадрах не зафиксированы отдельно
- Точные кривые easing и duration в мс — оценка по количеству кадров, не точное значение

## Общий вывод для промпта

Стилистически это не "вау-эффекты", а последовательный, тихий scroll-reveal с opacity+translate почти везде + один акцентный page-transition с blur. Ключевая деталь, которую стоит скопировать — стагтер (элементы/карточки появляются по очереди, а не пачкой) и то, что карточки кейсов не статичны, а "дораскрываются" контентом при скролле.
